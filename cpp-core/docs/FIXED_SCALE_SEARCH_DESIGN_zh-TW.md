# 固定尺度、允許旋轉、全圖搜尋：設計與改善方向

日期：2026-10-14。需求已確認：從實拍圖裁切模板，之後在**整張影像**找同尺寸物件，允許旋轉；不是先知道物件位置，也不是限定搜尋 ROI。其中原圖稀疏方向提案已完成[第16輪C++實作與量測](SPARSE_ORIENTATION_zh-TW.md)，保留研究選項；本文的FFT／旋轉基底等替代架構仍為設計，不代表已交付。

## 先分開固定尺度與金字塔

固定尺度將未知量由 `(x,y,θ,s)` 減為 `(x,y,θ)`，可以只準備一個尺度模型，並鎖住連續精修／救援的尺度。金字塔則把位置與角度搜尋先放到低解析度；即使物件沒有尺度變化，它仍可降低搜尋成本。

現有 C++ 可以直接做兩種固定尺度路徑：

| 路徑 | 設定 | 實際行為 |
|---|---|---|
| 固定尺度＋金字塔 | `scales={1.}`，原有 `minReducedArea` | 低解析度提案、原圖細搜尋、固定尺度連續精修 |
| 固定尺度＋原解析度 | `scales={1.}`，`minReducedArea=ceil(sqrt(w*h))²` | 只保留原圖 level0，不建立縮小層；原圖枚舉旋轉與位置，再局部精修 |

兩組都設 `stopLayer=0`，保持同一分數門檻、角度範圍、最大物件數及精修選項。不要只設 `minReducedArea=w*h`：目前為相容原版，會先取 `floor(sqrt(minReducedArea))²`，32×24 模板的768會變729而仍產生縮小層；784才足夠。這是實驗設定方法，尚不是新增的 GUI 模式或框選裁模板互動。

源碼：[Pattern建模](../src/image.cpp)、[搜尋與角度步進](../src/matcher.cpp)、[原生排程及鎖尺度](../experiments/research_pipeline.cpp)、[救援參數](../experiments/pose_ncc.cpp)。

## 為什麼直接移除金字塔可能慢很多

令全圖面積為 `N`、模板像素數為 `K`、枚舉角度數為 `A`。目前密集直接相關的主要成本約為 `O(A·N·K)`；實際還包含旋轉後畫布擴大、正規化、選峰和局部搜尋。

現有角度步進為 `Δθ=atan(2/max(w,h))`。64像素最大邊的模板搜尋全360°約需202角；縮小兩層後最大邊16，只需約52角。以1024²來源、64²模板估計，無金字塔粗搜尋約需 `202×961²×64²` 個乘積；縮小兩層則約 `52×241²×16²`，名義工作量差約988倍。**這是忽略畫布邊界與精修的算術估計，不是速度預測或本機實測倍數。**

省去一次金字塔建立，無法直接抵銷這個全圖重複搜尋量。另一方面，薄線、小字、低解析度下會消失的細紋理可能因保留原圖而改善漏檢；需透過獨立真值量測，不能預先認定一定比較準。

## 無金字塔高速版較值得研究的架構

### 1. 預編模板、保持來源圖固定

在模板改變時預先準備旋轉模板或特徵庫；每張新圖只建立一次來源資料。將來源分塊，讓相鄰位置與多個模板方向重用相同來源區域，再批次驗證少量候選。來源 tile 可帶 halo，但搜尋仍覆蓋全圖，不以真值提供 ROI。

旋轉模板的插值與目前旋轉來源不同，不能承諾逐位相等。旋轉後矩形外的填零也不能當物件背景計分，必須定義支撐遮罩；最終保留原模板 NCC 驗分，並測邊緣與插值偏差。若使用稀疏梯度或邊緣作候選提案，必須單獨量提案召回率：後段 NCC 無法救回根本沒送來的物件。

具體可試64／128／256個分散梯度點：來源建立一次方向回應圖，旋轉模板的點座標和方向，批次累加出候選，再沿用完整NCC及常駐精修。方向擴散與回應圖記憶體配置可參考 [Hinterstoisser等：Gradient Response Maps for Real-Time Detection of Texture-Less Objects](https://vincentlepetit.github.io/files/papers/comp_hinterstoisser_pami12.pdf)。這裡借用的是提案原理，沒有宣稱已移植該系統；稀疏分數也不是完整NCC的保證上界。

### 2. 遮罩 NCC＋FFT：同時處理所有平移

對角度 `θ` 的重採樣模板 `Tθ` 和二值有效支撐 `Mθ`，令 `nθ=ΣMθ`，`μθ=Σ(MθTθ)/nθ`，並令 `Kθ=Mθ(Tθ−μθ)`。對來源 `I`，以下相關運算皆以相同遮罩支撐計算：

```text
Pθ(x) = (I ⋆ Kθ)(x)
Sθ(x) = (I ⋆ Mθ)(x)
Qθ(x) = (I² ⋆ Mθ)(x)
Eθ    = Σ Mθ(Tθ−μθ)²
NCCθ(x) = Pθ(x) / sqrt(Eθ · [Qθ(x) − Sθ(x)²/nθ])
```

`⋆` 是互相關。零方差需明確處理，邊界只接受完整支撐；FFT需足夠零填充避免循環相關。`F(I)`、`F(I²)` 每張新圖可共用，模板與遮罩頻譜可在模板變更時準備。旋轉矩形的遮罩也跟著旋轉，**不能錯把分母當成所有角度共用的軸向矩形積分圖**。循序或分批角度可避免同時儲存全部角度分數圖。

這是將本題遮罩支撐展開後的推導，基礎來自 NCC 分子相關與分母正規化的分離；Lewis 的方法說明如何用變換域相關及局部統計計算 NCC，但沒有保證任意模板／尺寸下 FFT 都較快。[Lewis：Fast Normalized Cross-Correlation](https://scribblethink.org/Work/nvisionInterface/nip.html)

單角密集直接相關約 `O(NK)`；FFT在填充網格大小 `P` 上約 `O(P log P)`，但這裡有多個分子／遮罩統計變換與暫存。模板小、角度少時可能不划算。Metal 版需再量 FFT plan／模板建立、每幀來源變換、逆變換、選峰、GPU常駐記憶體與完整結果；尚未實作或量到本方案的 Metal FFT 加速。

這與之前的 log-polar／phase correlation 原型不同：先前嘗試從整塊內容估全域旋轉尺度；這裡仍是逐位置的局部模板分數圖。不能把先前全域配準失敗直接當作本方法已失敗，也不能把它當作已解決旋轉枚舉。

### 3. 旋轉基底／張量模板：減少角度枚舉

對足夠平滑的旋轉模板族，可研究近似展開 `Tθ≈Σ bₘe^(imθ)`：先算少量基底響應 `I⋆bₘ`，再合成不同方向的響應。其目的是讓相關次數由角度數 `A` 改為基底數 `B`；矩形遮罩與正規化統計也需一致處理。任意實拍高頻模板可能需要很多基底，截斷誤差、角度峰值與物件召回率必須一起測，不能直接聲稱精確旋轉不再付成本。方向濾波器的有限基底合成可參考 [Freeman與Adelson：The Design and Use of Steerable Filters](https://people.csail.mit.edu/billf/steerpaper.html)。

另一個直接相關的研究是把旋轉族整合到對稱張量模板，經分量相關恢復位置與方向。其論文提出數學方法，摘要所述巨大潛在收益特別針對3D；不是我們2D Metal流程的已驗證速度。[Almira等：Fast Normalized Cross-Correlation for Template Matching with Rotations，2024](https://arxiv.org/abs/2311.07561)

## 現有版本的改善優先順序

| 優先方向 | 原因 | 可驗證的下一步 |
|---|---|---|
| 固定尺度專用設定 | 需求直接排除尺度變化，無須跑多尺度模型 | 單尺度提案、精修／救援鎖尺度；和原多尺度成本分開 |
| 大量局部細搜尋 | 既有512物件耗時仍集中在proposal／fine | 重用來源tile與角度採樣、評估融合warp/NCC，保持候選與完整輸出契約 |
| 大圖記憶體副本 | 8K原生程序RSS仍高於Python參考 | 分開量RGB解碼暫存、來源持有、frame level0與pose建立，再減少副本 |
| 高分錯峰判斷 | 週期性影像可在錯位置仍有極高NCC | 次佳峰差、上下文與多解，量新增成本與FP／FN |
| 新無金字塔提案器 | 單純關金字塔仍保留巨大密集搜尋量 | 先驗證masked FFT或稀疏提案的全圖召回，再決定是否移植Metal |

固定尺度假設應另外測1%～數%的尺寸偏差；相機距離、焦距或拍攝平面變動可能違反這個假設。負控制用來界定適用範圍，不因模型刻意鎖尺度就把不符合假設的例子當成已解決。
