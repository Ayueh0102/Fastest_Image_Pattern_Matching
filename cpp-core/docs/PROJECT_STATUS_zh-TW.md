### 記憶體：已能從源碼定位的配置點

以下為配置路徑的靜態檢查，**不是已量出的 RSS 歸因或保證可回收的數字**。8192×8192 的 gray8、RGB888、float32 單通道邏輯像素容量分別為64、192、256 MiB；這些容量不能再與 RSS 直接相加。

- GUI 與原生 runner 目前先轉為 RGB888，再依自有係數轉灰階；即使輸入已經是灰階也經過這條路徑。可先評估保留原生灰階輸入，其他格式繼續使用相同灰階定義。
- `Session` 持有來源副本，`frame.prepare` 另建立來源金字塔第0層；這保證外部資料改動與非同步生命週期安全。減少副本必須保留明確的持有權與失效規則。
- 初次建立 pose 時，Session 建立 float 暫存，pose API 再複製進自有資料並中心化，Metal 另建立 buffer。這是精修初始化的配置點；前一輪8K場景只執行離散搜尋（core-only），不能拿 pose 配置來解釋該8K結果的記憶體差額。
- GUI 還有視窗、繪圖與上一份工作結果的持有關係；原生 runner 的 RSS 不能當作整個 GUI 程序 RSS。必須另量換圖、切換模式與閒置時的資源釋放。

## 本輪30分鐘驗證

使用既有最大512物件場景，固定 mode2＋overlap＋resident refinement／rescue，每100次重建 Session。檢查完整結果、工作量、緩衝區容量、非同步完成與記憶體成長；這是現有版本的生命週期驗證，不增加新圖像的準確度樣本。

**已完成並通過：1802.26 秒、534 次比對、5 次重建。** 全部輸出與非同步完成檢查通過；起末各106次的 RSS 中位數622.52→634.55 MiB（增加12.03 MiB，門檻62.25 MiB）。受測程式與輸入 SHA 不變；本輪沒有演算法改動。完整數據與界線見 [30分鐘報告](STABILITY_30MIN_zh-TW.md)。
