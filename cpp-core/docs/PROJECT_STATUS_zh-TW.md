> 2026-10-26第48輪：在macOS 27上拆開換來源與呼叫間空檔後，混合每影格多出的時間只剩pose重建與約1ms精修，候選搜尋的額外時間與8K fine4的GPU時間增加都沒有重現。見[每影格額外成本的來源](FRAME_OVERHEADS_zh-TW.md)。

2026-10-24穩定核心（非研究輪次）加入[ARM DOTPROD點積](CORE_DOTPROD_zh-TW.md)：GUI／CLI預設的`Backend::Auto`在有`__ARM_FEATURE_DOTPROD`的aarch64編譯改用UDOT（單一累加器、每4096 bytes歸約、遮罩尾端），其他ARM編譯照舊走NEON。輸出與原NEON、scalar逐位元相同（408次執行零差異）；Src7模式基準快13.7%（359.10→309.84ms），17張固定影像幾何平均快7.0%。舊OpenCV＋DOTPROD版仍快1.64倍，剩餘時間主要在旋轉、NCC其他部分與金字塔。第一個雙累加器候選使Src4慢9.9%，未採用但保留。

2026-10-25接著加入[精確旋轉與金字塔加速](CORE_WARP_PYRDOWN_zh-TW.md)：clang＋aarch64以NEON每次兩像素做`warp`，每一步照原scalar運算式的FMA合併方式；`pyrDown`的內部欄直接計算，全程整數。輸出與`51d95b1`逐位元相同（544次執行零差異，包括純scalar建置），Src7模式基準再快21.3%（319.76→251.49ms），17張固定影像每張都較快、幾何平均快22.7%。舊OpenCV＋DOTPROD版仍快1.32倍；`warp`在大模板仍占近一半，Src5／Src10改以`computeNcc`為主。

2026-10-25再改[窮舉NCC](CORE_EXHAUSTIVE_NCC_zh-TW.md)：預設窮舉路徑以精確整數欄和滑動求視窗和，取代binary64積分圖；UDOT建置一次計算8個相鄰視窗的點積，模板每個區塊只載入一次。有界限或screen的路徑不變。輸出與`65b7dad`逐位元相同（544次執行零差異），Src7模式基準再快37.6%（245.72→153.22ms），17張固定影像幾何平均快56.1%。穩定核心現在比同session的舊OpenCV＋DOTPROD版（186.22ms）快17.7%，稽核設定下17張也全部較快；剩下的時間以`warp`為主（大模板72～78%）。

第42輪[完整GPU粗選峰改為精確平行回合](GPU_PARALLEL_PEAKS_zh-TW.md)：新增`full_gpu_peak_mode=2`，多張分數圖同批、每回合平行接受與抑制，完整有序輸出與mode 1逐位相同。fine4完整GPU時間128／512少27.3%／34.4%（587.22／1881.34ms），每換新影格對混合為−31.4%／−22.7%，六物件混合仍快1.5%、8K快80.1%，皆6/6 block同向。1538次直接GT零FP／FN、0筆失敗門檻；完整GPU研究建議改為peak2／fine4，預設不變。

第43輪加入[細搜尋前的粗候選去重](CANDIDATE_DEDUP_zh-TW.md)，這是會改變語意、預設關閉的研究選項。k3在112／79個GT案例變體（混合／完整GPU）中沒有任何嚴格TP減少或FP增加，正式時間128／512物件混合少30.4%／37.0%、完整GPU少26.1%／25.7%（完整GPU臂用第40輪peak1／fine4，不與第42輪相乘），8K約不變。輸出不保證與基線逐位相同（matches相同者97/112、67/79）。k1與兩個刻意放寬的消融會失去物件，保留全部失敗；不改預設。

第44輪[去重疊在平行選峰上的實際速度](DEDUP_PEAK2_zh-TW.md)是量測輪，不改演算法：同一建置上，完整GPU peak2的k3對off靜態少35.5%／38.9%（128／512，各6/6），比第43輪在peak1上的−26.1%／−25.7%更多。每換一張影格時，完整GPU peak2＋k3在128、512與六物件都是四種組合中最快（384.13／1149.05／41.91ms，對混合k3 −39.0／−27.2／−11.4%）；8K上k3沒有差別。79個GT案例變體零退步，所有輸出與第43輪封存相同；保留4筆控制場景路徑不同的job比對失敗。預設不變。

第45輪[全CPU研究路徑對混合與完整GPU](CPU_PATH_zh-TW.md)是量測輪：每換一張影格時，全CPU（8執行緒、UDOT點積）在四個場景都最慢，128／512物件為3235.08／10236.80ms；混合快72.6／76.0%，完整GPU peak2＋k3快88.1／88.8%（8.4／9.0倍），六物件與8K也是6/6同向。CPU上k3同樣GT中立，112個案例變體的嚴格計數與Metal混合逐位相同。第一次正式計時被應用程式更新中止，依修訂保留不用並完整重跑。預設不變。

第46輪[物件內白參考的照明正規化同色驗證](ILLUMINANT_CHROMA_zh-TW.md)在測試樣本集 v1 上評估新的研究方法 `chroma_vk`（面板中位數估光源、von Kries 校正、遮罩內區域色度）。376 個異色物件誤收 0（含全部 isogray），既有遮罩色度在保留照明誤收 63/192；但事前登錄的第 95 百分位門檻太緊，保留照明同色只接受 31/88（白平衡偏暖 18/20 通過，局部暖光、JPEG、Blender 暖光／混合光未通過，過曝面板裁切而全部棄權）。依事前規則不推薦，保留為研究選項；既有方法輸出與改動前逐位相同，預設不變。

第47輪[有餘裕的事前門檻與物件內光梯度模型](CHROMA_MARGIN_zh-TW.md)為 `chroma_vk` 事前登錄新的門檻規則：τ 為「必須抓到的 ΔE00=4 變化」在無雜訊下最小區域色度距離的一半，只由標籤原稿決定（紅 0.00816、藍綠 0.01470），第46輪校準照明只用來檢查同色殘差 ≤ τ/2。以全新種子重產的保留集上，主方法有判定的同色 57/57 接受、ΔE≥4 異色 0/134 誤收（isogray 0/52），全部 17 項事前判定通過，推薦為研究用門檻；局部暖光仍有 11/20 同色因面板裁切棄權（端到端 9/20），過曝全部棄權。新增的線性光源模型 `reference_model: "linear"` 校準可行性藍綠未通過、梯度場景殘差反而較大（4／9，p=0.954），不推薦。第46、47輪於2026-10-26一起併入main；預設不變。

第48輪[每換一張影格的額外成本從哪裡來](FRAME_OVERHEADS_zh-TW.md)是診斷輪：runner新增預設關閉的靜態序列與呼叫間空檔選項，量{不換、換來源}×{無空檔、閒置、解碼}。換來源的成本是pose重建加約1ms精修；CPU在解碼的空檔幾乎沒有影響（8K混合影像準備+9.19ms例外）；閒置空檔則使混合慢31.6–42.3ms、完整GPU在512與8K慢5.6–6.9ms（8K幾乎都是主機端上傳，512約一半）；混合隨空檔變長而更慢，完整GPU在8K閒置10–30ms以上就多約5–6ms，之後不再增加。事前H2成立、H1為mixed、H3否定、H4／S1兩者皆非。4760次直接GT零FP／FN；不改預設。

第37輪補齊[完整Metal灰階搜尋資料路徑](FULL_GPU_zh-TW.md)，包含細搜尋控制、精修／救援及最終NMS；一次提交、最後一次等待。保留研究開關，原混合路徑與GUI預設不變。

第38輪完成[GPU分階段計時與精確分塊選峰](GPU_TILED_PEAKS_zh-TW.md)：128／512完整GPU耗時降低79.8%／87.3%，有序輸出不變；仍較混合慢15.5%／38.7%，細搜尋成為下一個主要瓶頸。

第39輪[分列快取與執行計數](GPU_FINE_TILES_zh-TW.md)證實原128／512完全未走過大ROI路徑，主改善目標未達。補充stop0可少約10%耗時，保留研究源碼；後續有界uint32、重疊統計及SIMD工作分配已由第40輪完成。

第36輪實作Metal粗NCC正規化、選峰與停止常駐：8K少物件有收益，大量候選顯著退步；保留研究選項與全部源碼，不改預設。見[常駐粗搜尋報告](COARSE_RESIDENT_zh-TW.md)。

第35輪加入真實密集RGB照片、49物件旋轉與異色控制，並整理校準、原始量測、失敗與來源。結果與界線見[本輪報告](STAGE35_REAL_RGB_zh-TW.md)。第34輪完成五項缺口的有界實驗，包含Blender、新影格、CPU／Metal公平比較及30分鐘持續運行；「完成實驗」包含證明某項方案無效，不等於所有場景通過。

## 本階段以外的研究缺口

| 缺口 | 已知原因或反例 | 下一個有意義的實驗 |
|---|---|---|
| 小模板粗搜尋召回 | 過深金字塔丟失可辨紋理；第35輪可由保留較高解析層改善，但有時間代價 | 依模板資訊量選擇層級；與固定512、原256、公平預算比較 |
| 遮擋與相似物身份 | 全局NCC漏候選或接受近似負例；增加預算無效 | 分區一致性／部分支撐、多峰歧義，保留無目標負控制 |
| 實拍顏色異常 | 前段漏搜；通道偏移可被NCC抵消；白平衡又可能觸發色度誤報。第46輪物件內白參考校正在渲染資料上分得開，但單類別門檻無法轉移到 JPEG、物件內光梯度與 Blender 混合光；第47輪原稿決定的有餘裕門檻在新保留集通過，但參考裁切時仍只能棄權（局部暖光 11/20、過曝全部），線性光源模型未改善 | 暗中性第二參考與事前登錄的覆蓋率門檻；多個正常外觀模板、小缺陷局部統計；先補實拍實例GT與正常樣本 |
| 更多GPU並行 | 第40輪三個精確NCC變體已完成；512新方案細搜尋約占GPU47.6%、粗選峰33.7%。第43輪的去重（改變語意）讓細搜尋減半，粗選峰成為最大階段 | 後續可另研究選峰／細搜尋分工或允許近似的架構；沒有證據已達極限，不能將階段時間當硬體利用率 |
| 多種模板庫、透視、離平面 | 尚未有完整場景與標註驗收 | 各自建立獨立benchmark，不能由同模板512物件外推 |

這些是後續研究項目，不代表要在本輪無限增加實驗。現階段可以交付可閱讀、可重建、可核對的專案；應按應用條件選用已通過的組合，對未通過場景保留限制。

## 審查時最容易混淆的三件事

1. 同一後端輸出一致，不等於GT準確；離線封存完整性通過也可以包含精度失敗。
2. RGB檔案輸入灰階搜尋、已知姿態RGB評分、全圖RGB搜尋、顏色缺陷檢測，是不同能力。
3. kernel加速、完整算法加速、初始化與實際相機吞吐量，是不同測量範圍。
