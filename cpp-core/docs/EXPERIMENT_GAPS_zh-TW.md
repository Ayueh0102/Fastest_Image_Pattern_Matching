# 截至第33輪的實驗缺口審查

這份審查將「現有功能可用」、「某次比較通過」與「已證明可泛化或最快」分開。已交付的灰階C++／Metal、Qt GUI與完整自有核心源碼可以繼續使用；研究尚未結束，優先工作也不只是GUI或穩定性測試。

## 應優先補的驗證

| 優先序 | 缺口與現有證據 | 下一個有意義的實驗／判準 |
|---|---|---|
| 1 | **不同模板的姿態精度。** 第32輪兩種512設定共用同一張合成圖；第33輪新增小模板已見高分卻尺度偏小 | 固定門檻與獨立GT，分開位置、角度、尺度與分數；掃描局部NCC目標確認偏差，再比較取樣／抗混疊處理。不能靠放寬尺度門檻消除失敗 |
| 2 | **遮擋、背景干擾與高分錯峰。** 舊近週期案例分數約0.999992卻偏8px；原救援依低分觸發，可能不處理高分錯峰 | 補相似但非目標、部分遮擋、接觸物件；記候選捕獲率與最後接受率，區分前段漏掉、求解錯峰及驗分拒絕。空白／雜訊無目標僅是簡單負控制 |
| 3 | **真正新相機影格與生命週期。** Session持有不可變來源；固定圖repeat不會重建所有資源 | 明確量每張新圖的解碼、建模、Session建立／銷毀、算法與峰值／穩態記憶體；再比較可重用模板及更新來源API。先做有界序列，再以約定30分鐘驗最新組合 |
| 4 | **最新最佳組合的消融。** mode1／2原先全流程測於較早固定尺度稀疏前段，第32輪多尺度仍mode0 | 第33輪固定同binary、前段與u8/shared，三路0／1／2，保留前段exact、最終一對一配對與GT。這只能回答組合收益，不能當全GPU極限 |
| 5 | **公平的CPU精修比較。** 多尺度Settings.backend同時改前段與精修；不能只設0就說僅換CPU精修 | 增加獨立精修後端選擇，固定同一前段和候選，CPU／Metal同預算比較。舊稀疏路徑有獨立searchBackend，其結果不能直接拼接最新多尺度時間 |
| 6 | **性能分布與硬體歸因。** 每組兩個程序較適合回歸檢查；48%慢樣本未重現但根因未確認 | 對值得採用的設定增加獨立block與隨機／平衡順序，保留尾端延遲；疑似慢點再做CPU排程與Metal時間線。GPU wait含device與排程，不代表全部是傳輸 |

第32輪combined repeat中，精修占快速約8.68%、完整次像素約1.34%。若其他部分完全不變，即使精修時間歸零，完整時間最多也只減少這些比例。這是當時量測下的理想上限，不是mode2的實測加速預測。後續仍要回頭改善占主要時間的前段細搜尋，但應先守住新場景的精度。

## 資料與統計仍需補什麼

第33輪新增兩個既有實拍模板的兩組新合成排列，共24個不同姿態；降質條件重用其中12個，不能算成另外12個獨立姿態。它們有獨立渲染幾何GT，但仍不是24張新相機實拍圖。正式前有功能pilot、沒有依結果改圖／門檻／分類，因此可稱固定的新驗證集，不稱完全盲測。

後續需要保存有授權的原始實拍與標註來源、物理像素／尺度定義、位置與角度標註不確定度，並把調參集、開發驗證集、最終保留集分開。兩個高度相似的設定、同圖不同噪聲或大量repeat，都不能增加獨立場景數。新模板小尺寸還需涵蓋高頻紋理、細線、低對比、週期和旋轉近對稱的不同種類。

準確度應至少同報：物件數、strict TP／FP／FN、較寬的位置定位、位置／角度／尺度誤差、前段候選覆蓋及失敗明細。沒有GT的Src4結果只能稱輸出一致或人工檢視，不能稱準確率100%。負場景沒有目標且沒有輸出，應報FP=0，不把分母為0的precision／recall強行寫成100%。

速度應分首次／repeat、算法／讀圖與建模，並同報峰值RSS及顯式容量。不同輪次、不同精修模式、不同前段不能相除得硬體倍率，也不能把GPU device、CPU wait與包住它們的總時間相加。共享CPU／GPU頁面只能算一次唯一容量。

## 已有證據但需要標明版本的項目

- 原始灰階C++核心、自有金字塔、旋轉、NCC、次像素與幾何流程已有來源及測試；Metal仍有CPU搜尋控制、驗分、救援與NMS，尚非全GPU。
- resident mode1／2的16384像素上限、513提案尾批、RGB／大模板拒絕、生命週期及GPU數值測試已有局部覆蓋。512物件不等於512提案；本案512場景有1301提案，融合精修需要拆批。
- 30分鐘／534次測試屬第14輪舊設定，baseline為`a989183`、overlap開啟；不能當作第32／33輪shared/u8/fine融合組合的持續運行證明。也沒有因這個缺口另要求24小時。
- 小幅約1%的差值目前只應描述為觀察值。通過10%性能容忍不等於更快、有統計顯著性或跨硬體可靠。
- 第29輪RSS失敗、第31輪48%慢樣本，以及所有共同準確度錯誤繼續保留。後續未重現或其他場景全過，不撤銷舊證據。

## 選配研究，不阻塞目前Metal版本

完整RGB全圖搜尋與GUI仍未交付；已有局部RGB評分／精修不等於完整三通道流程。Fourier原型仍包含CPU NumPy，裁切／背景干擾反例保留，全C++／Metal移植應先有採用收益證據。IC／ECC、旋轉基底、學習式提案、全GPU動態排程與多模板庫皆可獨立研究，不能假設必勝現有方法。

沒有CUDA硬體不妨礙繼續改善Metal。跨Apple硬體、Windows／Linux及CUDA驗證屬後續可移植性與性能研究；當前不把完整源碼等同於已在每個平台實測。
