正規化互相關 (NCC)

把模板像滑窗一樣在影像上移動，每個位置算一個「相似度分數」。

直觀理解

想像你拿著一張小照片（模板），在一面大牆壁（影像）上滑動比對。 每移到一個位置，你把模板和牆壁上對應的區域做比較—— 如果形狀完全一致，分數就是 1.0； 完全不相關就是 0.0； 反相（黑白顛倒）就是 -1.0。

NCC(x,y) = Σ [I(x+i,y+j) − μI] × [T(i,j) − μT] ──────────────────────────────────────────────── √{Σ (I − μI)²} × √{Σ (T − μT)²}
為什麼要「去均值」(零均值)? 去均值讓 NCC 對光照變化免疫。如果整體亮度提高（I → I + 50）， 去均值後 (I + 50) − μ' = I − μ，數值不變。 這對工業檢測很重要——光源不可能永遠一致。
Response Map 的尺寸 影像 H×W，模板 h×w → Response Map 大小 = (H−h+1) × (W−w+1)
每個像素代表模板左上角放在該位置時的分數。

影像金字塔

把影像逐層縮小一半，在小圖上搜尋比在大圖上快 4 倍。

3 1024

直觀理解

在 4000×3000 的照片中找一個 100×100 的螺絲釘，直接搜尋需要檢查 ~1200 萬個位置。
但如果先把照片縮小 8 倍到 500×375，模板也縮小到 ~13×13，只需檢查 ~18 萬個位置—— 快了 67 倍。找到大致位置後，再回到大圖精修。

pyrDown vs resize 使用 cv2.pyrDown（先高斯模糊再 ÷2 下採樣）， 而非 cv2.resize。
高斯模糊能避免混疊（aliasing）—— 想像把棋盤格直接縮小，會出現摩爾紋；先模糊再縮小就不會。

層數怎麼決定？

top_layer = 0 while 模板面積 > min_reduced_area (預設 256): 面積 ÷= 4 top_layer += 1

每層面積 ÷4（寬高各 ÷2），直到模板面積 ≤ 256 (≈ 16×16)。 模板太小會失去特徵，無法準確匹配。

分數門檻衰減

低解析度影像較模糊，NCC 分數自然偏低。因此每往上一層，門檻 ×0.9：

Layer 0: score = 0.80 (使用者設定) Layer 1: score = 0.72 Layer 2: score = 0.648 Layer 3: score = 0.583

旋轉搜尋策略

旋轉的是 Source 圖，不是模板——這是一個違反直覺但巧妙的設計。

0°

為什麼旋轉 Source 而非 Template？

效能考量 模板已經在 LearnPattern 中預計算了統計量（mean, norm）。 如果旋轉模板，每個角度都要重新計算。
旋轉 Source 後，直接用原始未旋轉的模板做 matchTemplate，統計量可以重用。

自適應角度步進

angle_step = atan(2 / max(模板寬, 模板高)) × 180/π

幾何意義：模板邊緣距中心 r = max(w,h)/2。 旋轉 angle_step 度後，邊緣點位移 ≈ r × sin(step) ≈ 1 pixel。 剛好不遺漏、不冗餘。

Top Layer 全域搜尋

在最小層窮舉所有角度，找到所有可能的候選位置。

搜尋流程

對每個角度 θ：

  1. 旋轉 Source：rotate_source(top_src, θ)，畫布自動擴張避免裁切
  2. 模板匹配：matchTemplate(rotated_src, top_tmpl) → response map
  3. Top-K 峰值：從 response map 中取前 K 個最高分，帶距離抑制
  4. 座標轉回：扣除旋轉造成的平移量 (trans_x, trans_y)
向量化 Top-K：比 C++ 更聰明的搜法 C++ 用 minMaxLoc 反覆找最大值（每次掃描整張圖）→ O(K × HW)。
Python 用 np.argpartition 一次找出前 K×50 候選 → O(HW) + O(候選數 × K)。
當 K 較大或圖較大時，Python 做法反而更快。

Coarse-to-Fine 逐層精化

從 Top Layer 的候選開始，逐層放大、精修位置與角度。

直觀理解

想像你用望遠鏡找鳥：

  • Top Layer：肉眼掃描天空，看到「那邊好像有東西」→ 粗略位置 + 方向
  • 中間層：望遠鏡低倍率，確認是鳥、調整指向
  • Layer 0：高倍率，看清是什麼鳥、精確位置

ROI 提取

不是在整張大圖重新搜尋，而是只裁切候選點附近的小區域（ROI = Region of Interest）。 ROI 大小 = 模板尺寸 + ±3 pixel padding：

ROI 尺寸 = (模板高 + 6) × (模板寬 + 6) matchTemplate → 響應圖 7×7 最大值位置 (3,3) = 候選恰在預期位置 偏移 ±3 = 有微調空間
旋轉 ROI 提取（GetRotatedROI） ROI 不是直接裁切矩形，而是用 warpAffine 做旋轉裁切。 這讓 ROI 中的影像「轉正」，可以與未旋轉的模板匹配。

三角度測試

每層精化同時測試 3 個角度：θ − Δ, θ, θ + Δ。 Δ 用該層模板尺寸重新計算（層越大、模板越大、步進越精細）。 取三者中最佳者傳給下一層。

次像素估計

整數像素已經不夠精確？在 3×3×3 鄰域擬合二次曲面，把精度推到 0.1 pixel。

直觀理解

matchTemplate 的峰值落在整數格點上（像素）。但真正的最佳位置可能在兩個像素之間。 就像量身高——用公分尺量是 170cm，但用更精密的尺可能是 170.3cm。

我們在峰值周圍取 3×3（或 3×3×3）個觀測值， 擬合一個二次曲面 z = ax² + by² + ...， 曲面的頂點就是真正的次像素位置。

27 點 3D 擬合（含角度）

z(x, y, θ) = ax² + by² + cθ² + dxy + exθ + fyθ + gx + hy + iθ + j 27 觀測點：3 角度 × 3 行 × 3 列 10 個未知參數 → 過定系統 → SVD 最小平方 Hessian：K1 = [[2a, d, e], [d, 2b, f], [e, f, 2c]] 梯度 ：K2 = [-g, -h, -i] 最佳點：δ = K1⁻¹ × K2
同時精修 x, y, θ 這不只是 2D 空間的次像素估計，還包含角度維度。 3 個角度層提供 θ 方向的梯度資訊，讓角度也能精確到 ~0.1°。
觸發條件很嚴格 只在以下條件全部滿足時才做 27 點擬合：
① Layer 0（最精細層）② 中間角度最佳 ③ 非邊界點 ④ 3 個角度層都有效
否則回傳整數位置——寧可不做，也不做壞。

非極大值抑制 (NMS)

同一個目標可能被多次偵測到——NMS 只保留最好的那個。

0.5

直觀理解

假設影像中有一顆螺絲。角度 30° 找到一個匹配（分數 0.95）， 角度 31° 也找到一個（分數 0.92），位置幾乎重疊。 NMS 保留 0.95 那個，淘汰 0.92。

三層加速

  1. 分數排序：高分優先處理，低分只需檢查是否與已保留的重疊
  2. AABB 預篩：先算軸對齊包圍框。如果 AABB 不重疊 → 旋轉矩形必然不重疊 → 跳過
  3. 精確交集：才計算旋轉矩形交集（昂貴操作，用 OpenCV 函式）
重疊度計算：不是 IoU 與一般物件偵測不同，這裡用的是 intersection_area / rect1_area， 分母是其中一個矩形的面積。 這代表如果小矩形完全在大矩形內，overlap = 1.0 → 會被抑制。 這與 C++ 原版邏輯一致。

FFT 加速 NCC

頻域乘法 = 時域卷積。模板越大，FFT 的優勢越明顯。

64px

核心公式

CC = IFFT( FFT(Source) × conj(FFT(Template)) )

複雜度比較

空間域 (OpenCV)

O(W × H × w × h)

模板每移動一格，重新計算 w×h 的乘積和

頻域 (FFT)

O(WH × log(WH))

一次 FFT → 頻域相乘 → 一次 IFFT。與模板大小無關！

Valid Region 的正確提取 FFT 輸出的 CC_full 尺寸 = (H+h−1, W+w−1)。 Valid 區域在左上角 [0 : H−h+1, 0 : W−w+1]， 不是 [h−1 : H, w−1 : W]。
這是 FFT NCC 實作最常見的 bug。

分母怎麼算？

FFT 只加速了分子（互相關）。分母需要每個滑窗的 sum(I) 和 sum(I²)。
用積分影像（Summed Area Table）一次建立 O(HW)， 之後每個滑窗 O(1) 查表——不管模板多大都是常數時間。

座標轉換全貌

從 Top Layer 旋轉座標到 Layer 0 原始座標——最容易搞混的部分。

轉換流程

① 旋轉後 Source 座標 (Top Layer) ─── matchTemplate 的輸出 ↓ ptRotatePt2f(pt, center, −angle) ② 原始 Source 座標 (Top Layer) ─── 候選的「真實」位置 ↓ × 2 放大 ③ 原始 Source 座標 (Layer i) ─── 放大到目前精化層 ↓ ptRotatePt2f(ptLT, center, +angle) ④ 旋轉後座標 → 減 (3,3) = ptPaddingLT ─── ROI 左上角 ↓ + maxLoc (ROI 內最大值位置) ⑤ 旋轉後 Source 座標 (Layer i) ↓ ptRotatePt2f(pt, center, −angle) ⑥ 原始 Source 座標 (Layer i) ─── 精化後的位置
旋轉公式 (ptRotatePt2f) 這是整個座標轉換的基礎函式：
x' = (x−cx)×cos + (y−cy)×sin + cx
y' = −(x−cx)×sin + (y−cy)×cos + cy
注意：這是「逆時針為正」的數學定義，與 OpenCV getRotationMatrix2D 一致。

最終輸出的角度

Python 中 match_angle 是「Source 旋轉的角度」。
輸出的 angle = −match_angle，意思是「模板需要旋轉此角度才能對上影像中的目標」。
例：影像中的目標順時針轉了 30° → match_angle = −30° → output angle = 30°。
